# .NET — Resumo semanal — 27/10/2026

**Período:** 20 a 27 de outubro de 2026 (horário de Brasília).

A semana exigiu atenção especial a **segurança do runtime e publicação de aplicações**. A Microsoft lançou patches emergenciais para .NET 8/9/10 e .NET 11 RC3; o Aspire recebeu correções sucessivas; Visual Studio e Copilot ampliaram ferramentas de agentes. Os itens abaixo priorizam decisões práticas em APIs, serviços e CI/CD.

## 1. Atualização emergencial de segurança: .NET 10.0.14, 9.0.22, 8.0.33 e 11 RC3

Em **25/10**, a Microsoft publicou atualizações fora do calendário mensal (*out-of-band*). Versões corrigidas:

| Linha | Versão |
| --- | --- |
| .NET 8 | **8.0.33** |
| .NET 9 | **9.0.22** |
| .NET 10 | **10.0.14** |
| .NET 11 (preview) | **RC3** |

O pacote corrige quatro vulnerabilidades: **CVE-2026-111497** (overflow na descompressão Brotli), **CVE-2026-114148** (metadados de ownership inseguros em tarballs Linux), **CVE-2026-70197** (corrupção de memória envolvendo SocketAsyncEventArgs) e **CVE-2026-102870** (debugger do Blazor WebAssembly). As duas últimas exigiram **republicação**, pois as correções de 13/10 não tinham resolvido completamente os problemas.

**Impacto prático:** aplicar novos runtimes e SDKs; para aplicações *framework-dependent*, atualizar o runtime do host e reiniciar; para *self-contained*, reconstruir e republicar; para containers, reconstruir a partir das imagens-base corrigidas. Estar apenas em 10.0.13, 9.0.21 ou 8.0.32 **já não basta**. Usuários do .NET 11 RC2 devem atualizar para RC3.

**Fonte:** [Microsoft — .NET October 2026 Out-of-Band Security Updates (25/10)](https://devblogs.microsoft.com/dotnet/dotnet-october-2026-oob-security-updates/).

## 2. Brotli: verificar os pontos reais de descompressão em APIs e workers

A **CVE-2026-111497** pode ser explorada quando aplicações processam dados Brotli não confiáveis por meio do middleware de descompressão de requisições do **ASP.NET Core**, de respostas com **HttpClient AutomaticDecompression** ou diretamente pelas APIs Brotli de **System.IO.Compression**. O comportamento automático de descompressão de requisições e respostas **não é habilitado por padrão**; o .NET Framework não é afetado por essa falha.

**Impacto prático:** conferir middlewares, clientes HTTP e bibliotecas de ingestão/compressão, especialmente em APIs abertas e jobs que processam dados de terceiros. A avaliação de exposição deve olhar o caminho de código efetivamente usado, sem substituir a aplicação do patch.

**Fonte:** [Microsoft — descrição e mitigação da vulnerabilidade Brotli](https://devblogs.microsoft.com/dotnet/dotnet-october-2026-oob-security-updates/).

## 3. App Service e Azure Functions: rollout não significa runtime atualizado

Em **26/10**, a Microsoft detalhou a implantação dos patches no Azure:

- **App Service Linux:** rollout concluído no canal *Latest*; canal *Standard* ainda em implantação controlada.
- **App Service Windows:** rollout em andamento via *Safe Deployment Practices*, ainda não concluído.
- **Azure Functions:** rollout Linux em andamento; Functions Windows depende do servicing do App Service Windows. Static Web Apps com Functions gerenciadas também seguem em implantação.

**Impacto operacional:** verificar a versão do runtime **do processo em execução**, em cada instância, e não somente o SDK instalado ou a linha de runtime configurada. Containers próprios e aplicações self-contained **não** são corrigidos automaticamente pelo runtime gerenciado da plataforma. Em AKS, conferir os novos digests implantados após rebuild/redeploy.

**Fontes:** [App Service Linux (26/10)](https://azure.github.io/AppService/2026/10/26/dotnet-brotli-security-update-app-service-linux.html) · [App Service Windows (26/10)](https://azure.github.io/AppService/2026/10/26/dotnet-brotli-security-update-app-service-windows.html) · [Azure Functions (26/10)](https://azure.github.io/AppService/2026/10/26/dotnet-brotli-security-update-azure-functions.html).

## 4. Aspire 13.6.2–13.6.4: correções de segurança, logs e confiabilidade

O **Aspire** recebeu três versões de manutenção entre **20 e 24/10**:

- **13.6.2:** fixa MessagePack em 2.5.307 por correções de segurança.
- **13.6.3:** corrige travamento de operações do AppHost quando consumidores deixam de ler *resource watches*; atualiza o Developer Control Plane para 0.26.6.
- **13.6.4:** melhora inicialização/timeout de recursos, corrige publicação Azure em AppHosts TypeScript com propriedades enum parametrizadas e restringe permissões de logs diagnósticos no Unix: arquivos **0600** e diretórios dedicados **0700**.

**Impacto prático:** se o ambiente usa Aspire 13.6, validar atualização para **13.6.4** e testar start/stop, dependências e observabilidade. Logs podem conter URLs sensíveis, inclusive de login do dashboard; restringir acesso e evitar anexá-los sem revisão.

**Fontes:** [Aspire 13.6.4 — release oficial](https://github.com/microsoft/aspire/releases/tag/v13.6.4) · [Histórico 13.6.2–13.6.4](https://github.com/microsoft/aspire/releases).

## 5. Visual Studio 2026: Copilot BYOM passa a depender de novo Agent

Em **22/10**, o GitHub anunciou melhorias do Copilot no Visual Studio: o **Git agent** pode analisar pull requests anexados ao chat, usando MCP do provedor Git; o **BYOM (Bring Your Own Model)** permanece em preview e passa a exigir o **Agent (Preview)** baseado no harness do **GitHub Copilot SDK**. Os modos anteriores Ask e Agent deixam de suportar BYOM, e configurações Ollama antigas precisam ser refeitas. A lista de erros do **NuGet Audit** ganhou ação de remediação assistida, dependente do NuGet MCP Server.

**Impacto arquitetural:** distinguir o *harness* (sessão, ferramentas, autorização) do *provider* do modelo. Antes de habilitar reparos automáticos de vulnerabilidades, exigir revisão de dependências, build e testes, além de limitar permissões do MCP.

**Fonte:** [GitHub — Copilot in Visual Studio, atualização publicada em 22/10](https://github.blog/changelog/2026-10-22-github-copilot-in-visual-studio-september-update-2/).

## 6. NuGet.org: chaves antigas expiram em 01/11

O prazo anunciado pela equipe do NuGet ficou imediato: em **01/11/2026**, expiram **todas as API keys do NuGet.org criadas antes de 17/08/2026**. Desde 17/08, novas chaves têm validade máxima de **30 dias**. A recomendação é migrar os pipelines elegíveis para **Trusted Publishing com OIDC**, eliminando a necessidade de guardar credenciais de publicação de longa duração.

**Impacto prático:** revisar pipelines com publicação de bibliotecas em NuGet.org, rotacionar chaves como contingência e preferir tokens curtos atrelados à identidade de workflow. O prazo afeta o *push* de pacotes, não o *restore* de pacotes já publicados.

**Fonte:** [Microsoft — Strengthening NuGet Supply Chain Security](https://devblogs.microsoft.com/dotnet/strengthening-nuget-supply-chain-security-reducing-api-key-lifetime/).

## 7. Copilot Assisted Permissions chega à disponibilidade geral

Em **26/10**, o GitHub lançou **Assisted Permissions** no Copilot CLI, aplicativo Copilot e **VS Code**: solicitações de execução de comandos, acesso a arquivos e URLs são avaliadas por modelo. Operações classificadas como claramente seguras podem seguir; as demais exigem aprovação. Administradores empresariais podem definir políticas e restringir o modo **Allow All**.

**Impacto arquitetural:** reduzir aprovações repetitivas sem conceder permissão irrestrita; ainda é necessário manter sandbox, identidade de mínimo privilégio e auditabilidade. O anúncio **não** declara essa funcionalidade GA no IDE Visual Studio.

**Fonte:** [GitHub — Assisted Permissions GA (26/10)](https://github.blog/changelog/2026-10-26-github-copilot-assisted-permissions-generally-available/).

## 8. Métricas de coding agents passam a mostrar skills, MCP e clientes

Em **22/10**, a API de uso do Copilot passou a identificar por nome *skills*, agentes customizados, servidores MCP, comandos e plugins; as listas passam de cinco para **25 entradas**. Em **23/10**, surgiu **totals_by_client**, agregando solicitações, sessões e consumo de tokens por cliente (incluindo VS Code, Copilot CLI, Codex e OpenCode).

**Impacto prático:** avaliar adoção e custo de ferramentas de engenharia agentiva em vez de medir apenas mensagens ou linhas de código. **Atenção:** request_count contabiliza chamadas ao modelo, **não** tarefas concluídas; identificação do cliente é *best effort*. Não usar essas métricas isoladamente como prova de produtividade.

**Fontes:** [GitHub — métricas de skills e MCP (22/10)](https://github.blog/changelog/2026-10-22-custom-skills-agents-and-mcp-servers-in-usage-metrics-api/) · [GitHub — métricas por cliente (23/10)](https://github.blog/changelog/2026-10-23-usage-metrics-api-adds-usage-from-tools-like-opencode/).

## 9. GPT-6.1 Terra no Copilot: avaliar com tarefas reais de C#

Em **26/10**, o GitHub anunciou **GPT-6.1 Terra** para Copilot, com disponibilidade gradual em **Visual Studio, VS Code, CLI e cloud agent**. O modelo é posicionado para coding agentivo e tarefas de terminal a custo menor que GPT-6.1 Sol. O fornecedor relata ganhos iniciais em tarefas C# e de terminal frente a GPT-5.6 Terra — **não se trata de benchmark independente**.

**Impacto prático:** comparar em suites próprias de C#: alterações multiarquivo, aderência a padrões, testes, compilação, regressões, latência e custo por tarefa concluída antes de padronizar um modelo.

**Fonte:** [GitHub — GPT-6.1 Terra no Copilot (26/10)](https://github.blog/changelog/2026-10-26-gpt-6-1-terra-in-github-copilot/).

## Prioridades desta semana

1. **Imediato:** aplicar os patches OOB do .NET; reconstruir/republicar self-contained e containers, verificando efetivamente as instâncias implantadas.
2. **Segurança de APIs:** mapear uso de descompressão Brotli em endpoints e clientes HTTP.
3. **Até 01/11:** corrigir credenciais antigas de publicação no NuGet.org.
4. **Aspire:** instalar e testar 13.6.4 caso a linha 13.6 esteja em uso.
5. **Evolução:** validar BYOM/Agent Preview e políticas de permissões em ambiente controlado.

**Contexto de roadmap:** o suporte ao **.NET 8 e .NET 9 termina em 10/11/2026**; planejar a migração para uma linha suportada, com preferência pelo **.NET 10 LTS** quando a longevidade for decisiva. [Fonte oficial — fim do suporte .NET 8/9](https://devblogs.microsoft.com/dotnet/dotnet-8-9-end-of-support/).

**Sinal da semana:** segurança da distribuição e do runtime teve impacto mais imediato do que novas APIs de C#, EF Core, gRPC ou SignalR. Não há anúncio de release estável significativo dessas três últimas áreas confirmado nesta janela.
