# .NET — Resumo semanal — 13/10/2026

**Período:** 06 a 13 de outubro de 2026, até a manhã de terça-feira (horário de Brasília).

O destaque da semana não foi uma nova versão do runtime: os movimentos mais relevantes foram **performance de ferramentas, Native AOT, novas opções de pooling e controles operacionais para coding agents**.

## 1. C# Dev Kit 11: arquitetura nova e ganhos expressivos em grandes soluções

Em **06/10**, a Microsoft apresentou o C# Dev Kit 11.0 para VS Code. A extensão, antes na série 3.3, foi reconstruída em torno de um servidor **Native AOT** consolidado, cache de projetos e prioridade para o arquivo ativo.

Em benchmarks oficiais, uma solução com **407 projetos (Aspire)** passou de até **84,1 segundos para 0,47 segundo** até o arquivo ativo ficar utilizável. O build incremental sem alterações caiu de **34,4 para 0,88 segundo**. O consumo de memória dos processos do Dev Kit caiu de **2.072 MB para 316 MB** nesse cenário. Os números **não incluem** o Roslyn, que roda separadamente, nem o VS Code.

A versão também oferece análise semântica para `.csproj`, `.props` e `.targets`, além do **C# Doctor** para problemas de SDK, restore e ambiente.

**Aplicação:** avaliar cold start, warm start, compilação incremental e memória em solutions grandes e worktrees usados por agentes. Os resultados são do fornecedor e dependem do repositório.

**Fonte:** [Microsoft — A faster, lighter C# Dev Kit (06/10)](https://devblogs.microsoft.com/dotnet/faster-lighter-csharp-dev-kit/).

## 2. Microsoft.Data.SqlClient 7.1: Pool V2 com criação paralela de conexões

Em **06/10**, a Microsoft detalhou o **Pool V2**, disponível no `Microsoft.Data.SqlClient` **7.1.0**. A nova implementação usa `System.Threading.Channels` e pode abrir múltiplas conexões simultaneamente em um pool, reduzindo a espera no início da aplicação e durante picos de demanda.

Em benchmark Linux com 100 chamadas concorrentes, o tempo do teste assíncrono caiu de **604,1 ms para 92,0 ms** (6,6 vezes mais rápido). Esses números **não** representam aceleração de SQL nem de pools já aquecidos.

A funcionalidade é opt-in. Configure **antes** de abrir qualquer conexão:

```csharp
AppContext.SetSwitch("Switch.Microsoft.Data.SqlClient.UseConnectionPoolV2", true);
var builder = WebApplication.CreateBuilder(args);
```

O recurso funciona com EF Core e Dapper. **Trade-off:** parte do caminho de `OpenAsync` ainda usa chamadas de rede síncronas sobre threads gerenciadas, exigindo monitoramento do ThreadPool sob alta latência.

**Aplicação:** testar em APIs com cold starts ou grande concorrência de criação de conexões, comparando p95, p99 e uso de threads. Manter rollback pelo switch.

**Fonte:** [Microsoft — Try SqlClient's new connection pool (06/10)](https://devblogs.microsoft.com/azure-sql/try-sqlclients-new-connection-pool-for-faster-parallel-connections/).

## 3. Aspire 13.6: Native AOT no dashboard, mas Blazor ainda experimental

Em **06/10**, o time do Aspire detalhou a migração do dashboard para **Native AOT**. A Microsoft reportou **66% menos tempo mediano** até a página se tornar visível, dispensando JIT no startup e a dependência de um runtime instalado separadamente.

O caso reuniu **Blazor Web App, Fluent UI, Minimal APIs, gRPC/OTLP, SQLite e Dapper**. As adaptações envolveram trimming, reflection, serialização source-generated e Dapper.AOT.

**Ressalva essencial:** o suporte Native AOT utilizado pelo dashboard com Blazor é **experimental** no .NET 11 RC1. Isso **não equivale** a suporte geral para publicar Blazor Web Apps com Native AOT.

**Aplicação:** estudo de caso para arquiteturas AOT; verificar dependências que fazem reflection ou geração dinâmica e validar builds publicados, não somente testes sob JIT.

**Fonte:** [Aspire — Bringing Native AOT to the dashboard (06/10)](https://devblogs.microsoft.com/aspire/aspire-dashboard-native-aot/).

## 4. Aspire explica persistência: SQLite e Dapper em vez de tudo na memória

Em **08/10**, o time publicou um aprofundamento técnico da persistência do Aspire 13.6, apresentada na edição anterior. Logs, traces, métricas e estado dos recursos podem ser consultados depois de reiniciar o AppHost.

Os limites padrão de console logs, structured logs e traces passaram de **10 mil para 100 mil** cada. Em benchmark da equipe, a memória privada caiu de **1.007 MB para 241 MB**, redução de 76%.

Foi escolhido **Dapper**, em vez de EF Core, para controlar filtros, contagens, ordenação e paginação diretamente em SQLite. Para o dashboard standalone, há modos `None`, `Run` e `Resume`.

**Aplicação:** caso concreto de trade-off ORM versus SQL controlado e de redução de memória por paginação. Atenção ao armazenamento local de informações de telemetria que possam ser sensíveis.

**Fonte:** [Aspire — Adding persistence to the dashboard (08/10)](https://devblogs.microsoft.com/aspire/aspire-dashboard-persistence/).

## 5. VS Code 1.141: segurança para agentes e worktrees

**07/10:** VS Code 1.141 trouxe sandboxing para agentes em Windows, macOS e Linux; GitHub anunciou a disponibilidade geral do sandbox local em Copilot CLI, aplicativo e Agent Host. Os controles restringem acesso a arquivos e rede, mas não substituem segurança de endpoint. O editor também ganhou limpeza de worktrees inativos e continuidade de sessões externas, incluindo Codex.

**Aplicação:** restringir acesso do agente aos diretórios, feeds e conexões necessários para build e testes.

**Fontes:** [VS Code 1.141](https://code.visualstudio.com/updates/v1_141) · [GitHub — sandbox local GA](https://github.blog/changelog/2026-10-07-local-sandboxing-for-github-copilot-now-generally-available/).

## 6. OpenTelemetry dos agentes com atribuição opcional

**12/10:** o GitHub passou a permitir atributos `user.name`, `process.user.name` e `host.name` em traces do Copilot. Captura de identidade, prompts, respostas, argumentos e saídas de tools segue desligada por padrão e é configurável por classe.

**Aplicação:** auditoria e atribuição de uso sem obrigatoriamente coletar código ou conteúdo das conversas.

**Fonte:** [GitHub — telemetria de agentes](https://github.blog/changelog/2026-10-12-client-telemetry-user-attribution-and-configurable-capture/).

## 7. Dependabot e registries de organização

**12/10:** registries acessíveis anonimamente agora podem ser cadastrados na configuração de organização para Dependabot, inclusive mirrors de pacotes. Um feed apenas no `nuget.config` não é automaticamente liberado nos jobs do serviço.

**Aplicação:** padronizar acesso de múltiplos repositórios a mirrors NuGet sem tokens artificiais.

**Fonte:** [GitHub — registries anônimos](https://github.blog/changelog/2026-10-12-anonymous-organization-level-registries-for-dependabot/).

## 8. .NET 8 e 9: suporte acaba em 10/11

**Alerta de prazo:** .NET 8 LTS e .NET 9 STS encerram suporte em **10/11/2026**. O destino recomendado é **.NET 10 LTS**, suportado até novembro de 2028. Esta manhã, o canal oficial ainda listava **.NET 11 RC1** como último prerelease.

**Ação:** inventariar frameworks, containers, SDKs de CI e hosting; concluir testes e rollout antes do prazo.

**Fontes:** [Microsoft — fim do suporte](https://devblogs.microsoft.com/dotnet/dotnet-8-9-end-of-support/) · [Releases .NET](https://github.com/dotnet/core/releases).
