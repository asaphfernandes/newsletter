# Front-end — Resumo semanal — 27/10/2026

**Período:** 20 a 27/10/2026 (até 09h, horário de Brasília). **Foco:** TypeScript, segurança do runtime JavaScript, Next.js, Vite, pnpm e novidades da Web Platform.

## 1. TypeScript 7.1 Beta inaugura a nova API de ferramentas e content mappers

**20/10.** A Microsoft publicou o **TypeScript 7.1 Beta**. A mudança mais importante para ferramentas é a API nativa dividida em entradas como `typescript/sync`, `typescript/async`, `typescript/fs` e `typescript/ast`. A API expõe análise sintática/semântica e exige descarte explícito de objetos (`using` ou `dispose`) para liberar recursos do compilador em Go.

Os **content mappers** permitem integrar formatos com TypeScript embutido (Vue, Astro, Svelte, MDX e outros), criando uma representação virtual com mapeamento para o arquivo original. A execução no CLI exige `--runExternalCode`; o editor exige confiança e permissões. Também chegaram declarações para **import attributes**, suporte a **source phase imports** e `--target es2026`. O compilador ficou mais rigoroso com restrições de tipos condicionais distributivos.

Nos benchmarks publicados pela equipe, o typecheck de `mui-docs` caiu de **22,2 s para 11,9 s**, enquanto o uso de memória caiu de **8.093 para 4.079 MiB** (resultados do fornecedor, não garantia para outros projetos).

**Impacto arquitetural:** abre caminho para lint, análise estática, plugins e integrações com componentes de arquivo único sem depender da antiga API monolítica. **Ação:** experimentar em branch de ferramentas, validar extensões e compiladores integrados e não promover o beta diretamente para todos os builds de produção.

**Fonte:** [Microsoft TypeScript — Announcing TypeScript 7.1 Beta](https://devblogs.microsoft.com/typescript/announcing-typescript-7-1-beta/).

## 2. Node.js: atualização de segurança crítica para SSR, toolchain e CI

**21/10.** Foram lançados os patches **Node.js 24.22.1 LTS**, **22.23.4 LTS** e **26.12.1 Current**. O conjunto corrige problemas de validação de certificados TLS e resolução DNS, além do **CVE-2026-111497**: uma falha de escrita fora dos limites no decodificador Brotli que, quando a aplicação descomprime entrada maliciosa, pode causar corrupção de memória ou execução remota de código.

A atualização também endurece o reuso de conexões HTTP, o modelo de permissões e componentes internos. As três linhas recebem correções relevantes, embora a lista exata varie por versão.

**Impacto:** aplicações React com SSR, Next.js, proxies Node, testes e agentes de build podem depender do runtime afetado. **Ação:** atualizar imagens Docker, runners e ambientes de produção para o patch da linha suportada; testar tráfego HTTPS, DNS e descompressão. Não considerar que uma atualização do framework substitui a correção do runtime.

**Fontes:** [Node.js — Boletim de segurança de 21/10](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) · [Node 24.22.1 LTS](https://github.com/nodejs/node/releases/tag/v24.22.1) · [Node 22.23.4 LTS](https://github.com/nodejs/node/releases/tag/v22.23.4) · [Node 26.12.1](https://github.com/nodejs/node/releases/tag/v26.12.1).

## 3. Chrome 156: retry de módulos JavaScript e IndexedDB sobre SQLite

**20/10.** O Chrome **156** passou ao canal estável de desktop. Uma mudança relevante para SPAs é deixar de armazenar permanentemente em cache **falhas de carregamento de módulos**: depois de uma falha de rede, a aplicação pode tentar novamente um `import()` dinâmico.

Outro avanço é a migração do backend de **IndexedDB para SQLite** em *novos* armazenamentos. A API JavaScript permanece igual; dados existentes em LevelDB não são migrados nesta etapa. A versão inclui ainda cabeçalhos customizados no handshake de **WebTransport** e melhorias de CSS, como `random()` e novas combinações de `overflow`.

O anúncio de distribuição estável informa também **353 correções de segurança**.

**Impacto arquitetural:** rotas lazy-loaded e microfrontends devem testar recuperação após falhas transitórias de download de chunks; aplicações offline/PWA devem manter testes de persistência e migração de dados em diferentes navegadores. A melhoria no retry **não** elimina a necessidade de tratar erros de chunk e deploys com versões incompatíveis.

**Fontes:** [Chrome — anúncio da versão estável (20/10)](https://chromereleases.googleblog.com/2026/10/stable-channel-update-for-desktop_02018666648.html) · [Chrome Platform Status — Chrome 156](https://chromestatus.com/release-notes/156).

## 4. Next.js 16.4.3 estabiliza runtime, observabilidade e bundlers

**23/10.** O **Next.js 16.4.3** trouxe um patch estável de backports, sem incorporar todas as mudanças do canal Canary. Entre as correções estão evitar carregar o runtime App Page dentro de `proxy.ts`, melhorar a continuidade de **traces OpenTelemetry por request**, corrigir URLs de Google Fonts sem extensão e desfazer uma alteração problemática de invalidação de loaders no Turbopack.

**Impacto arquitetural:** rastreamento distribuído inconsistente e efeitos de bootstrap do runtime dificultam a investigação de problemas em SSR, middleware/proxy e produção. **Ação:** atualizar projetos 16.4.x e testar traces, proxy, fontes e o comportamento de rebuild. Os recursos da série 16.5 Canary não devem ser tratados como estáveis.

**Fonte:** [Next.js — v16.4.3](https://github.com/vercel/next.js/releases/tag/v16.4.3).

## 5. pnpm 12.16 melhora supply chain, scripts e monorepos

**26/10 (UTC: 27/10).** O **pnpm 12.16.0** adicionou `--env-file` global repetível para scripts e comandos, suporte controlado à atualização de `pnpm-lock.yaml` quando o lockfile é um symlink e a opção `pnpm setup --no-modify-path`.

A mesma versão corrige **problemas de processamento de zstd** e uma implementação de assinatura suscetível a vazamento de chave por análise de tempo. Há ainda ajustes em instalação concorrente de workspaces, cache de side effects e pacotes com variantes diferentes de peer dependencies.

**Impacto:** melhora a consistência de builds e a segurança da cadeia de pacotes. **Ação:** revisar versões pinadas pelo `packageManager` e Corepack, testar `--frozen-lockfile` no CI e migrar de forma controlada, especialmente quando scripts de lifecycle usam variáveis de ambiente.

**Fonte:** [pnpm — v12.16.0](https://github.com/pnpm/pnpm/releases/tag/v12.16.0).

## 6. Vite 8.3.5 corrige resolução de chunks e pré-carregamento

**21/10.** O **Vite 8.3.5** corrigiu casos de *chunk import maps* ausentes e incluiu dependências de preload no hash desses mapas. Também passou a aplicar corretamente `server.origin` às URLs de assets no modo de desenvolvimento empacotado, além de ajustes de comportamento do servidor.

**Impacto arquitetural:** em aplicações com code splitting, preloads e assets distribuídos por CDN, pequenos erros de mapeamento podem resultar em falhas só depois do deploy. **Ação:** atualizar o patch, validar navegação com carregamento preguiçoso e verificar cache busting e preloads em build de produção.

**Fonte:** [Vite — v8.3.5](https://github.com/vitejs/vite/releases/tag/v8.3.5).

## 7. Safari 27.2 reforça formulários nativos, acessibilidade e consistência de CSS

**26/10.** A Apple publicou o **Safari 27.2** com refinamentos no *Customizable Select*, incluindo o pseudo-elemento **`::field-content`** para estilizar a opção selecionada sem exigir `<selectedcontent>`. O navegador atualizou a propriedade de Grid Lanes de `flow-tolerance` para **`fit-tolerance`**, mantendo temporariamente o nome anterior como alias depreciado.

Entre as **20 correções**, destacam-se problemas de **VoiceOver com regiões `aria-live`**, elementos ancorados em `<dialog>`, ativação transitória que afetava a Clipboard API e falhas de mídia/WebRTC.

**Impacto:** componentes de formulário e design systems podem depender menos de selects totalmente customizados, mas precisam de fallback e teste de compatibilidade. **Ação:** revisar CSS experimental e testar teclado, leitores de tela, diálogos e clipboard no Safari.

**Fonte:** [WebKit — WebKit Features for Safari 27.2](https://webkit.org/blog/18515/webkit-features-for-safari-27-2/).

## 8. create-vite retoma TypeScript 7 em templates, com correção imediata

**27/10.** O **create-vite 9.3.2** voltou a selecionar **TypeScript 7** onde há suporte nos templates, depois de um recuo feito na versão 9.3.1 da semana anterior. A versão **9.3.3**, lançada no mesmo dia, corrigiu a inclusão dos arquivos de template no pacote publicado.

**Impacto:** o gerador pode criar projetos com versões diferentes das usadas pela sua base existente. **Ação:** pinagem de versões nos templates internos e validação de `typecheck`, build e teste inicial antes de adotar o scaffolding novo.

**Fontes:** [create-vite 9.3.2](https://github.com/vitejs/vite/releases/tag/create-vite%409.3.2) · [create-vite 9.3.3](https://github.com/vitejs/vite/releases/tag/create-vite%409.3.3).

## Prioridades da semana

1. **Segurança:** atualizar Node.js nos ambientes SSR, de build e CI; revisar o patch do pnpm.
2. **Qualidade de deploy:** testar chunks dinâmicos e preloads após atualização de Chrome, Next.js e Vite.
3. **Evolução de tooling:** avaliar TypeScript 7.1 Beta e sua nova API/content mappers sem confundir funcionalidades beta com suporte estável.
4. **Compatibilidade:** testar Safari 27.2 em formulários, diálogo, acessibilidade e Web APIs.

**Sinal da semana:** o maior ganho está na **confiabilidade do runtime, do pipeline de build e dos limites browser/servidor**. Não houve necessidade de inflar a edição com pequenas atualizações do React ou de bibliotecas de estado sem impacto arquitetural relevante.
