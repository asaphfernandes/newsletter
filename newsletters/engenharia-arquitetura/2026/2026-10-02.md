# Engenharia e Arquitetura — Resumo — 02/10/2026

Janela principal: **30/09 a 02/10/2026**. Os movimentos mais interessantes foram em **modernização incremental, resiliência comprovável, engenharia de plataforma para CI/CD, AppSec e integração orientada a eventos**.

## Modernização: Datalex evita o big-bang rewrite de um legado de 4 milhões de linhas

A AWS publicou um caso da Datalex, cujo sistema crítico de reservas possui cerca de **4 milhões de linhas de código**.

Em vez de reconstruí-lo do zero, a equipe selecionou um slice representativo e migrou de **EJB2/Java 8 para Spring Boot/Java 21**, preservando o máximo possível da lógica existente.

O uso do **Strangler Fig Pattern** permite alternar requisições entre a REST API antiga e a versão modernizada.

**Insight:** modernizar runtime e criar uma camada compatível pode ser muito menos arriscado que reescrever o domínio.

## Alta disponibilidade: Multi-AZ precisa ser provado durante dias

A AWS publicou uma abordagem de **evacuação completa de uma Availability Zone por 48–72 horas**.

Um failover curto valida o mecanismo de troca, mas não o comportamento sustentado: connection pools, DNS TTL, scaling drift, novos deploys em N-1, capacidade e reintrodução da AZ.

**Trade-off:** operar realmente em N-1 exige capacidade suficiente nas zonas restantes.

## GitHub Actions Runner Controller: runners Kubernetes exigem arquitetura de control plane

O Actions Runner Controller trouxe melhorias para instalações com muitos ephemeral runners e runner scale sets.

Quando a escala cresce, passam a importar reconciliation rate, API-server pressure, controller concurrency, graceful shutdown e comportamento durante upgrades.

**Trade-off:** self-hosted runners dão controle de rede e ambiente, mas transferem à organização a responsabilidade por um control plane que runners hospedados escondem.

## AppSec: vulnerability reporting ganha schema, validação e backpressure

O GitHub passou a permitir formulários estruturados para vulnerability reporting e adicionou rate limits por reporter.

O padrão é o mesmo usado em sistemas distribuídos:

```text
Reporter
   ↓
Schema
   ↓
Validation
   ↓
Rate limiting
   ↓
Security queue
   ↓
Triage
```

**Trade-off:** exigir demais afasta pesquisadores legítimos; permitir volume ilimitado cria DoS operacional.

## CI/CD: histórico do pipeline não é armazenamento permanente

Checks, workflow runs e statuses passaram a seguir políticas de retenção.

**Impacto arquitetural:** se resultados de pipeline são evidência de deploy, aprovação, testes, security gates ou compliance, devem ser exportados para um sistema com retenção adequada.

## Kafka continua avançando como backbone de integração entre SaaS

Conectores gerenciados para Dynamics 365 e Marketo reforçam o padrão de reduzir integrações ponto a ponto usando Kafka como backbone.

Mas connectors não eliminam decisões sobre schema evolution, ordering, retries, rate limits, DLQ e idempotência.

## Sinal da edição

A direção é **menos confiança em diagramas e configurações, mais evidência produzida pelo comportamento real do sistema**.
